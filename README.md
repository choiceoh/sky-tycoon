# Sky Tycoon — 항공사 경영 시뮬레이션

코에이의 **에어매니지먼트 II** 계보를 잇는 턴제 항공사 경영 시뮬레이션.
세계 45개 도시를 무대로 슬롯을 확보하고, 노선을 열고, 기재를 갈아 끼우며
시나리오가 끝날 때 기업가치 1위에 오르거나 경쟁사를 전부 삼키는 것이 목표다
(시대에 따라 20년 · 16년 · 17년).

**Kotlin Multiplatform + Compose Multiplatform.** 화면 한 벌로 안드로이드와 데스크톱이 함께 돌아간다.
기준 화면은 **안드로이드 폰 세로**이고, 넓은 화면에서는 사이드 레일 + 2단 레이아웃으로 펼쳐진다.

## 폰에서 바로 해보기

**[최신 APK 내려받기](https://github.com/choiceoh/sky-tycoon/releases/download/nightly/sky-tycoon-debug.apk)**
— `main` 이 갱신될 때마다 CI 가 다시 올리므로 링크는 그대로다.
설치하려면 안드로이드에서 "알 수 없는 출처의 앱 설치"를 허용해야 한다 (디버그 서명이라 스토어 배포용은 아니다).

### "앱이 설치되지 않음" 이 뜬다면

1. **예전 빌드가 깔려 있는 경우 — 지우고 다시 받는다.** 2026-08-18 이전 nightly 는
   빌드마다 서명 키가 달랐다(레포에 디버그 키스토어가 없어 CI 가 매번 새로 만들었다).
   안드로이드는 서명이 다른 APK 를 기존 앱 위에 덮어 깔지 못하고 이 메시지만 띄운다.
   한 번만 지우면 되고, 그 이후 빌드끼리는 그냥 덮어 설치된다. 지우면 세이브도 함께 사라진다.
2. **"알 수 없는 출처" 허용** — 브라우저·파일 관리자 등 APK 를 여는 그 앱에 권한이 붙는다.
3. **Play 프로텍트** — "알 수 없는 개발자" 경고에서 그냥 설치를 눌러야 한다.
4. **안드로이드 8.0(API 26) 이상**이어야 한다. 그 아래는 설치가 되지 않는다.
5. 위가 다 아니면 받다 만 파일일 수 있다. 다시 받아본다 (정상 파일은 16MB 남짓이다).

## 모듈

| 모듈 | 내용 |
|---|---|
| `core` | 시뮬레이션 전부 (순수 Kotlin, UI 의존 없음). 수요·시장점유·원가·AI·이벤트·주식 |
| `app` | Compose Multiplatform 공용 UI + 데스크톱 실행 엔트리 |
| `android` | 안드로이드 껍데기 (Activity 하나). **Android SDK 가 있을 때만 빌드에 포함된다** |

`settings.gradle.kts` 가 `ANDROID_HOME` / `local.properties` 를 보고 SDK 유무를 판단한다.
SDK 가 없는 환경(CI 컨테이너 등)에서도 `core` 와 `app`(데스크톱)은 그대로 빌드·테스트된다.

## 실행

```bash
./gradlew :app:run          # 데스크톱 창으로 플레이
./gradlew :core:jvmTest     # 시뮬레이션 테스트 (밸런스·규칙·20년 완주)
./gradlew :app:screenshots  # X 서버 없이 주요 화면을 PNG 로 렌더 → app/build/screenshots
```

안드로이드 (SDK 가 설치된 머신에서):

```bash
./gradlew :android:assembleDebug     # APK
./gradlew :android:installDebug      # 연결된 기기에 설치
```

APK 는 `~/.android/debug.keystore` 가 아니라 레포에 있는 `android/debug.keystore` 로 서명된다.
그래야 어느 머신에서 빌드하든, CI 가 올린 nightly 든 서명이 같아 폰에서 서로 덮어 설치된다
(디버그 전용 키다 — 스토어 배포에는 쓰지 않는다). `tools/verify_apk_signer.py` 로 확인할 수 있다:

```bash
python3 tools/verify_apk_signer.py android/build/outputs/apk/debug/android-debug.apk
```

## 게임 규칙 요약

**턴 = 1분기.** 시나리오는 제트 여명기(1970~), 메가캐리어 전쟁(1990~), 현대의 하늘(2012~).

- **슬롯** — 공항마다 주간 슬롯 총량이 정해져 있고 모든 항공사가 나눠 갖는다.
  주간 왕복 1회에 양쪽 공항 슬롯이 하나씩 필요하다. 슬롯은 사는 게 아니라 **빌리는 것**이라,
  가벼운 취득 수수료와 **매 분기 임차료**로 나뉜다. 놀리는 슬롯도 임차료는 그대로 나가므로
  안 쓰면 반납해야 한다 — 이 고정비가 호황과 불황의 낙차를 만든다(영업 레버리지).
- **환승** — 직항이 채우지 못한 좌석은 **허브를 경유하는 연결 수요**가 메운다.
  그래서 노선 하나의 값어치가 뒤에 깔린 네트워크에 달려 있다. 로컬 수요만 보면 시원찮은
  스포크도 허브에 승객을 물어다 주면 살아난다.
- **수요** — 도시쌍마다 **정치·경제 비중**(출장)과 관광 매력(레저)에서 수요가 나온다.
  출장 수요는 GDP 만 따라가지 않는다 — 수도에는 정부·외교·국영기업 통행이 붙고,
  그 나라가 클수록 그 몫이 커진다. 경제 규모만 재면 제2세계의 수도인 모스크바가
  상파울루와 같은 칸에 놓이고 베이징이 상하이보다 낮게 잡힌다. 그래서 수도는 둘을
  합쳐, 수도가 아닌 경제 중심지(프랑크푸르트·상파울루·상하이)는 경제만으로 매긴다.
  두 세그먼트는 성격이 다르다. 출장객은 운임에 둔감하고 편수·서비스를 보고,
  관광객은 정반대다. 그래서 운임 전략이 곧 손님의 종류를 고른다.
- **시장 점유** — 같은 구간의 항공사들이 다항 로짓으로 승객을 나눠 갖는다.
  운임·편수·서비스·브랜드·안전 신뢰도에 더해, **부대시설**(양 끝의 호텔·라운지 등),
  **보유 환승편**(그 공항에서 뻗는 다른 취항지 수), **기반 국가**(홈 공항이면 온전히,
  같은 권역이면 절반)가 효용에 들어간다. 그래서 같은 기재를 같은 운임에 띄워도
  네트워크와 연고가 있는 쪽이 확실히 더 채운다.
- **로컬 항공사** — 게임에 나오는 아홉 회사는 그 시대의 **주요 항공사**다. 나머지 수요는
  모델에 없는 지역 사업자들이 낮은 경쟁력으로 실어 나른다고 본다. 이들이 모든 도시쌍에서
  바깥 선택지로 늘 겨루므로, **내놓은 좌석이 무조건 팔리지 않는다** — 로컬보다 매력이
  있어야 팔린다. 탑승률이 곧 경쟁력의 함수다.

  로컬의 실력은 한 값으로 고정돼 있지 않다. **거리가 멀수록 약해지고**(태평양을 건널
  광동체를 굴릴 회사는 대개 이미 게임 안에 있다), 그 위에 **도시쌍마다 종 모양으로
  흩어진다** — 억센 국적사가 버티는 구간이 있고 손 놓은 구간이 있다. 그래서 같은 수요·
  거리라도 채워지는 정도가 달라, **취항 전에 시장을 살펴보는 일**이 값어치를 갖는다.
  편차는 도시쌍 이름에서 결정론적으로 뽑으므로 분기마다 출렁이지 않고 세이브도 재현된다.

- **거리대별 성격** — 운임은 **0km 기본요금 + 거리요금**이다. 착륙료·회항처럼 거리를 안
  타는 원가가 많아서, 기본요금이 없으면 짧은 노선일수록 고정비를 못 건진다. 그래서
  단거리는 편수를 욕심내면 바로 적자로 넘어가고(좌석을 깔수록 로컬에 밀린다), 장거리
  광동체는 **로컬 수요만으로는 애초에 못 채운다** — 도쿄–LA 의 분기 수요는 747 한 대를
  최대로 굴렸을 때 내놓는 좌석보다 작다. 그 자리를 메우는 것이 허브 연결 수요다.
- **진영** — 제작사가 셋으로 갈린다. **미국기**(보잉·더글러스·록히드)와
  **구소련기**(투폴레프·일류신·야코블레프)는 서로 넘어가지 못하고, **유럽기**(에어버스·
  포커·BAC·ATR…)는 양쪽 다 산다 — 유럽 제작사가 두 진영 사이의 중립 공급처다.

  | 기종 | 서방 항공사 | 모스크바 기반 |
  |---|---|---|
  | 미국 | 언제나 | 1991년까지 불가 |
  | 유럽 | 언제나 | 언제나 |
  | 구소련 | 불가 | 언제나 |

  소련기는 값이 싸고 기름을 먹으며 브랜드값이 안 붙어, 기재값을 아끼는 대신 운항비를
  계속 무는 반대쪽 극단이 된다.

- **객실 배치** — 회사마다 바닥의 몇 %를 비즈니스 객실에 내줄지 정한다. 앞자리 한 석이
  이코노미 2.2석의 바닥을 쓰므로 **총 좌석이 줄고**, 대신 앞자리 손님은 3.4배를 낸다.
  다만 출장 수요 전체가 앞자리 값을 내지는 않아서(프리미엄 수요는 그중 일부다),
  크게 깔면 빈 채로 난다 — 게다가 **빈 앞자리도 유지비가 나간다**. 그래서 "최대치가
  답"이 아니라 노선망의 출장 비중에 맞춰야 하는 값이 된다 (대개 20% 안팎에서 꺾인다).

- **앞자리 수요는 대접을 따라간다** — 출장객 중 몇 %가 앞자리 값을 내는지는 회사마다
  다르다. **서비스 등급 · 브랜드 인지도 · 양 끝 공항의 라운지·호텔**이 그 비율을 밀고
  당긴다. 평범한 회사는 출장객의 22%, 서비스 5등급에 라운지를 낀 회사는 40% 넘게
  받는다. 그래서 객실 크기의 정답이 회사마다 갈린다 — 대접에 투자한 쪽은 30~35%까지
  깔아도 남고, 그러지 않은 쪽은 20%가 한계다.

- **브랜드는 체감한다** — 광고 효과는 √지출이다. 알려지기는 싸고 유명해지기는 비싸다.
  정비례로 두었더니 분기 24만 달러면 상한 100 에 눌러앉아 **세 해 만에 아홉 회사가
  전부 100** 이었다 — 이름값이 모두 같으면 이름값은 변수가 아니다. 그 지역 부대사업도
  광고비로 환산돼 같은 곡선 안에서 더해진다.

- **경쟁사 AI** — 플레이어와 **똑같은 명령 계층**(`Actions`)만 사용한다.
  AI 가 규칙을 우회하는 일이 구조적으로 불가능하다.
- **인수합병** — 지분 50%를 넘기면 회사를 통째로 삼킨다. 한 분기 매입 상한은 10%,
  지분이 쌓일수록 매집 단가가 오르고, 당하는 쪽은 **유상증자로 희석**해 방어할 수 있다.
  매입 상한과 증자 한도는 모두 **분기 누적**으로 잰다 (한 분기에 나눠 사서 우회할 수 없다).
- **부대사업** — 슬롯만 사둔 도시가 아니라 **취항 중인 노선이 있는 도시**에만 낼 수 있다.
  정비창은 전사에 하나만 두면 되고(할인이 회사 단위로 적용된다) 두 번째는 아예 막힌다.
- **역사 이벤트** — 두 차례 오일쇼크, 미국 규제완화, 플라자 합의, 걸프전, 아시아 외환위기,
  9·11, 화산 폭발, 올림픽 특수까지 연도에 맞춰 터진다.

## 밸런스를 만질 때

수치는 전부 `core/src/commonMain/kotlin/skytycoon/core/sim/Balance.kt` 한 파일에 모여 있다.
`core/src/commonTest` 의 `BalanceTest` 가 기준 노선의 수지를 지켜본다:

- 독점 **간선 여럿의 중앙값**이 마진 12~55% (확장할 맛이 나야 한다). 도시쌍 하나로 재지
  않는 건 로컬 경쟁력이 노선마다 흩어져 있어서다 — 한 노선의 수치는 그 노선이 어떤 값을
  뽑았는지를 잴 뿐이다
- 3사 경쟁이 붙으면 마진이 확실히 깎이고 탑승률이 떨어진다
- 같은 기재·운임·편수라도 **연고와 환승편이 있는 쪽이 확실히 더 채운다**
- 경쟁 시장에서 운임을 올리면 승객을 뺏긴다
- 800km 아래 단거리도 편수를 맞추면 남는다. 대신 편수를 최대로 밀면 적자다
- 허브를 붙이면 장거리 광동체가 채워지고, 그 환승 수요가 **스포크에 고루 퍼진다**

`CabinTest` 는 객실 크기가 **판단거리로 남아 있는지**를 지킨다: 최대치가 최적이면 실패하고,
대접이 좋은 회사(서비스·브랜드·라운지)가 더 크게 깔 수 있어야 통과한다. `RegressionTest` 는
광고 효과가 체감하는지를 — 정비례로 돌아가면 아홉 회사가 다 같이 상한에 눌러앉는다 — 지킨다.

`DiagnosticTest`·`FunDiag`·`FareCurveDiag`·`SeedProbe`·`HomeProbe`·`PremiumProbe` 는 `@Ignore` 로
꺼 두었다. 각각 분기별 손익 흐름, 캠페인 지표, 거리대별 운임 곡선, 시드 편차, 홈 시장 크기,
프리미엄 매력도 분포를 눈으로 보고 싶을 때만 켠다.

### 화폐 단위 주의

운임·원가 상수는 **시나리오 시작 시점의 명목 달러**다. `World.inflation` 이 해마다 함께 밀어 올린다.
반면 기재 카탈로그 가격은 이미 시대별 명목가(747-100 = 4,500만 달러)라 물가를 곱하지 않는다.
새 상수를 추가할 때 이 구분을 지키지 않으면 시나리오마다 수지가 어긋난다.

### 수요 스케일

실제 서울–도쿄는 연 수백만 명이 오가지만 그대로 쓰면 여객기 한 대(주 14왕복 = 분기 5만 4천 석)가
시장에 아무 흔적도 남기지 못해 운임도 경쟁도 무의미해진다. 그래서 수요를 게임 스케일로 압축했다 —
간선 노선 하나가 항공사 두세 곳을 먹여 살리는 정도. 승객 1명은 현실의 여러 명에 해당하는 추상 단위다.

## 세이브

`GameState` 전체가 `kotlinx.serialization` 으로 직렬화되는 순수 데이터라 JSON 한 덩어리가 곧 세이브다.
난수도 상태(`rngState`)가 세이브에 실리므로 같은 시드는 같은 전개를 재현한다.

**분기를 넘길 때마다 자동 저장된다.** 안드로이드는 백그라운드에서 프로세스가 통째로 정리될 수 있어서,
저장이 없으면 20년짜리 캠페인이 소리 없이 사라진다.

슬롯은 **둘**이고 역할이 다르다. 시작 화면의 "이어서 하기"는 자동 슬롯을 되살리고,
재무 화면의 저장 버튼은 수동 슬롯에 되돌아갈 지점을 찍는다 (되돌리기가 그 지점을 읽는다).

| 슬롯 | 파일 | 쓰는 시점 |
|---|---|---|
| `AUTO` | `auto.json` | 분기를 넘길 때마다 · 세이브를 불러온 직후 |
| `MANUAL` | `manual.json` | 재무 화면에서 저장 버튼을 눌렀을 때만 |

저장 위치는 진입점이 정한다 (`SaveStorage.current`) — 데스크톱은 `~/.skytycoon/` 아래 두 파일,
안드로이드는 앱 전용 저장소. 교체 도중 죽는 경우에 대비해 직전 세이브가 `.bak` 으로 남고
읽을 때 그것까지 본다. 테스트에서는 메모리 구현으로 갈아 끼운다.

## CI

`.github/workflows/ci.yml` 이 모든 PR 과 `main` 푸시에서 돌린다:

1. `:core:jvmTest` · `:app:desktopTest` · `:app:compileKotlinDesktop` — 시뮬레이션 규칙과 공용 UI
2. `:app:screenshots` — X 서버 없이 주요 화면을 렌더 (PNG 아티팩트)
3. `:android:assembleDebug` — **APK 조립까지 해야** 안드로이드 전용 코드가 검증된다.
   러너에 SDK 가 있어 `settings.gradle.kts` 가 `:android` 를 빌드에 넣는다.
   이 스텝이 없으면 `MainActivity`·매니페스트·안드로이드 세이브 구현이 한 번도 컴파일되지 않은 채
   그린 체크로 머지될 수 있다.
4. `tools/verify_apk_signer.py` — 조립된 APK 의 서명 인증서가 `android/debug.keystore` 것인지 대조한다.
   키가 어긋나도 빌드는 초록불로 끝나고 APK 도 멀쩡해 보인다 — 폰에 덮어 설치할 때야
   "앱이 설치되지 않음" 으로 드러나므로, 배포 전에 여기서 잡는다.

`main` 푸시에서는 만들어진 APK 를 `nightly` 릴리스에 갈아 끼운다 (위 다운로드 링크가 그것).
`versionCode` 는 CI 실행 번호(`SKY_TYCOON_BUILD_NUMBER`)로 매 빌드 올라가고,
`versionName` 에 커밋 해시가 붙어 폰의 앱 정보에서 어느 빌드인지 확인할 수 있다.
